# 案例：10 分钟汇报，把续费率从 71% 做到 80%

## 用户需求

> 帮我把下季度的续费改进方案做成 PPT 大纲，10 分钟，给 VP 看，要批 2 个交付人力。

默认假设：决策者=VP、10 分钟、目标=拿到 2 个人力与方案批准。

## 反面示范（用户最初的版本）

```
P1 封面：续费改进方案
P2 目录
P3 背景
P4 现状数据
P5 问题分析
P6 用户画像
P7 竞品分析
P8 解决方案
P9 实施计划
P10 总结
```

脚本结果（`--minutes 10`）：

```
页数        ：10（10 分钟建议 6–10 页）
结论在前 3 页：否
废页        ：9
非判断句标题：0
评分        ：0/100

废页（没有独立判断，删掉或合并）：
  - P2 目录
  - P3 背景
  - P4 现状数据
  - P5 问题分析
  - P6 用户画像
  - P7 竞品分析
  - P8 解决方案
  - P9 实施计划
  - P10 总结
```

**0 分。** 十页里有九页没有任何判断——它们是"标签"，不是"观点"。听众看完只知道"你讲了续费"，不知道"你要我做什么"。

这也是最典型的 PPT 病：**把 Word 的章节标题直接搬成了幻灯片标题**。

## 重写后的大纲

```markdown
# 一句话结论
听完之后希望 VP 批准 2 个交付人力 + 小客户包拆分方案，因为他会相信：
小客户流失不是因为价格，而是因为从没被教会用核心功能。

P1 封面：把续费率从 71% 拉到 80%，只需三件事
P2 结论：小客户不用核心功能是流失主因，需要 2 个人力补交付 — 请今天批
P3 现状：续费率卡在 71% 一整年，距目标差 9 个点，代价年化 380 万
P4 拆解：流失的 63% 集中在小客户（<50 人），核心功能使用率只有 12%
P5 归因：不是价格，是没被教会 —— 30 个流失客户里 27 个从未用过批量导入
P6 证据：3 家试点客户核心功能使用率提到 61%，6 个月续费 100%
P7 方案：拆小客户包（快、便宜）vs 加交付人手（慢、有效），建议两个都做
P8 计划：Q4 分两批推，需 2 名交付 + 1 名产品，11/10 前到位
P9 风险：交付人力招不满会拖慢试点，备选是把第二批延到 Q1
P10 请求：批准 2 名交付编制 + 小客户包拆分，最晚本周五
```

脚本结果：

```
页数        ：10（10 分钟建议 6–10 页）
结论在前 3 页：是
废页        ：0
非判断句标题：0
评分        ：100/100
```

`--strict` 也可以挂进 CI：只要出现废页或名词短语标题，退出码就是 1，团队里谁都不许交"目录 + 背景 + 总结"式的 PPT。

## 把 10 页标题连起来读

> 把续费率从 71% 拉到 80%，只需三件事 → 小客户不用核心功能是流失主因，需要 2 个人力补交付 → 续费卡在 71% 一年，距目标差 9 个点 → 流失的 63% 集中在小客户，核心功能使用率只有 12% → 不是价格，是没被教会 → 3 家试点客户 6 个月续费 100% → 拆包快但不够，加人慢但有效，建议都做 → Q4 分两批推，需 3 个人 → 招不满会拖慢试点 → 批准编制与拆包，最晚本周五

**这一段就是整份 PPT。** 这段读不通，PPT 一定讲不通；如果只读标题就能做决定，这份 PPT 就成了。

## 这个案例做对了什么

1. **删掉 9 页废页**，信息量没有减少——背景并入 P3，竞品内容因为不影响结论直接砍了。
2. **结论页在第 2 页**，且写了「请今天批」，让 VP 从第 1 分钟就知道要做什么决定。
3. 每个论点都有**一个数字 + 一个 so what**（63%、12%、27/30、100%）。
4. 方案页给了**两个方案的代价**，而不是只推自己想做的。
5. 最后一页是请求，不是「谢谢」。
6. 标题控制在 40 字内（脚本会在超长时报错），保证投影和手机上都能一眼读完。
